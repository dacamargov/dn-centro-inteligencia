# Evidencia de ejecución — ML (hacerlo inteligente)

> Prerrequisito: **ML or Gen AI — make the solution intelligent**
> Modelo clásico de ML que predice **riesgo de quiebre de stock** por tienda ×
> categoría, entrenado con scikit-learn, registrado en **MLflow + Unity Catalog
> Model Registry** y servido por **inferencia batch** a una tabla gobernada.
> (Esto es *adicional* a los agentes de Gen AI documentados en `04_genai.md`.)

## Problema de negocio

Hoy el quiebre de stock se **descubre** cuando el auditor llega a la tienda. El
modelo lo **anticipa**: estima la tasa de quiebre esperada por combinación
tienda × categoría a partir de contexto estructural (categoría, canal, cadena,
país, mezcla cliente/competencia, promoción) — sin usar campos derivados del
propio `en_stock`, para evitar fuga de etiqueta.

## Entrenamiento

Código: `src/ml/entrenar_riesgo_quiebre.py` — job `DNCentro ml — entrenar riesgo de quiebre`.

```
run_id MLflow : 32a70af31c21471288d772083f39e09b
modelo        : GradientBoostingRegressor (sklearn Pipeline + OneHotEncoder)
n_train       : 414   (filas tienda×categoría)
n_test        : 139
features      : categoria, canal, cadena, country_code,
                share_cliente, promo_rate, confianza_prom
hiperparams   : n_estimators=250, max_depth=3, learning_rate=0.05
```

### Métricas registradas en MLflow (leídas vía API `/mlflow/runs/get`)

| métrica | valor | lectura |
|---|---:|---|
| `mae` | **0.0551** | error absoluto medio de la tasa de quiebre |
| `baseline_mae` | 0.0681 | predecir siempre la media del train |
| `mejora_vs_baseline_pct` | **19.0 %** | el modelo supera al baseline en 19% |
| `r2` | 0.2026 | varianza explicada |

> El baseline (media) ya es exigente porque la tasa de quiebre es relativamente
> estable; aun así el modelo recorta ~19% el error, suficiente para **ordenar**
> correctamente dónde priorizar reposición.
